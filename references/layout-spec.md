# 罗魁最终版版式规范

## 版式目标

复现参考PDF的结构、视觉层级、信息密度和阅读顺序。下面的测量来自最终版页面；字体无法取得时使用接近的中文字体替代，不宣称逐像素一致。

| 元素 | 参考值与执行方式 |
| --- | --- |
| 纸张 | A4竖版，参考页面约595.2×841.8pt；正文单栏 |
| 左右边界 | 左约36pt，右约36—40pt，可用宽约520—523pt |
| 姓名 | 顶部居中，约20pt黑体/粗体，蓝色#2F5496；有照片时在照片左侧区域居中 |
| 基本信息 | 姓名下两行，约10.8pt；蓝色标签、黑色内容；只展示用户提供的信息 |
| 照片 | 用户提供正常证件照时置右上；参考矩形约x468.6、y37.6、宽85.9、高120.2pt；不得拉伸或用无关图像代替 |
| 教育区起点 | 参考首个模块标题约y101pt；照片延伸至教育区域时，照片左侧文字和横线须缩短避让 |
| 模块标题 | 约12pt蓝色黑体/粗体，左对齐；下方约1.8pt黑色横线，延伸到当前可用右边界 |
| 正文 | 约10.2pt，黑色，中文微软雅黑或相近的清晰字体，英文数字可配Times New Roman |
| 行距 | 紧凑，约13.8—14.2pt；避免大段空白和过大的段后间距 |
| 经历标题行 | 日期左、名称居中、项目类型/角色右；约10.2—10.8pt加粗；长名称可续一行，禁止相互覆盖 |
| 三段正文 | “项目背景：”“我的工作：”“项目成果：”标签加粗；三个独立段落，顶格、满行、无项目符号、无悬挂缩进 |
| 重点加粗 | 三段标签必加粗；工作段通常选二至四个关键技术或本人贡献短语，成果段选一至两个核心结果；技能与自评选核心能力，正文粗体通常约15%—25%，不把整句背景或整段都加粗 |
| 页尾 | 个人技能与自我评价，默认保留个人技能和有经历支撑的自我评价，必要时加入成果总结；自评约70—110字，模仿具体事例、能力及本人特点的自然表达 |
| 公司标识 | 真实任职或合作公司经主体核验后使用官方logo，放在对应公司名称旁；高约10—12pt、宽不超过24pt，等比缩放，不替代公司文字 |
| 页尾留白 | 有足够内容时末行宜距页底约32—48pt；避免下半页大面积空白，不为填满而塞入无关信息 |

## 固定模块顺序

个人信息 → 教育背景 → 科研经历 → 项目经历 → 实习经历 → 个人技能与自我评价。

没有科研就省略科研，没有实习就省略实习，不留空栏。不要把技能放到教育后，也不要为了匹配JD自行改成另一套版面。只有用户另行指定顺序时才调整。

## 内容与排版的接口

1. 每个条目先完成三段正文，再排版。不得让排版程序把工作段拆成自定义小标题或要点。
2. “我的工作”可包含首先、其次、然后、最后等连接词，正文自然换行；不是每个连接词另起项目符号。
3. 一页内容过多时，先压缩重复背景、冗长课程、重复荣誉和空泛学习描述；保留关键技术细节、真实职责及三段标签。
4. 默认正文10.2pt；微调范围约9.8—10.5pt。低于9.8pt仍超出时不要继续缩字，重新精简或保持同版式分页。
5. 未提供姓名/联系方式、日期或成果的，禁止借用参考人的信息。必要信息不足时先列待补项；不要在可投递正文中生成“某某”“待填”等占位。
6. 科研标题过长时允许两行，第二行仍需与角色保持边界；教育区有照片时控制文字宽度，不能遮住照片。
7. 页面偏空先恢复真实且相关的技术细节、交付与自评，再调整段距和字号；不只把姓名或标题放得很大。先保证阅读舒适，再追求饱满。
8. 教育没有成绩信息时先询问，按[成绩与排名规则](grades-self-evaluation-logos.md)处理；未经确认的GPA、均分或排名不得由排版脚本补齐。

## 默认Word输出

使用`scripts/render_resume_docx.py`，依赖`python-docx`及共用校验模块所需的`reportlab`，复用以下JSON结构；文字和粗体均以可编辑段落、真实字体样式保存。使用定位制表位排日期、名称、角色，正文不放入表格或图片。

```bash
python scripts/render_resume_docx.py resume.json resume.docx --font-size 10.5 --line-spacing 14.2 --paragraph-space 1.0
```

默认中文字体微软雅黑，英文Arial；渲染环境无对应字体时使用清晰的中文替代字体。A4、左右36pt、上下约32—36pt，保持同一视觉规范。参数负责密度，不能保证页数，必须使用文档工作流的`render_docx.py`渲染所有页并看PNG后调整。若超过一页先精简重复内容；若偏空优先恢复相关事实，再调字号、行距与段距。带正常证件照时按文档工作流额外处理照片避让，脚本不静默丢弃照片。

## 固定版式渲染器

`scripts/render_resume.py`依赖`reportlab`，用用户环境中可嵌入的中文常规/粗体TTF字体。输入UTF-8 JSON。`**文字**`会加粗；其他文字原样呈现，不支持任意HTML。

```json
{
  "profile": {
    "name": "使用当前求职者提供的姓名",
    "contact_lines": ["当前求职者的联系方式", "其他已提供的基本信息"],
    "photo": null
  },
  "education": [
    {
      "institution": "学校",
      "degree": "专业与学历",
      "dates": "原件提供的时间",
      "details": ["已有成绩排名或研究方向"]
    }
  ],
  "honors": "已有且精选的荣誉，可省略",
  "sections": [
    {
      "title": "科研经历",
      "entries": [
        {
          "dates": "原件提供的时间",
          "name": "真实项目或公司名称",
          "role": "真实角色或实习岗位",
          "background": "只填背景正文，不重复项目背景标签",
          "work": "只填连贯工作段正文",
          "results": "只填已证实的成果正文"
        }
      ]
    }
  ],
  "summary": {
    "skills": "已有技能",
    "achievements": "准确的成果总量与状态",
    "evaluation": "有事例支持的自评"
  }
}
```

以上是字段说明，不是可直接投递的简历数据。`sections`只使用科研经历、项目经历、实习经历；渲染器按上述顺序排列。输入没有相应经历就不创建该模块。`profile.photo`为输入JSON所在目录的相对路径或绝对路径，不提供时不画照片。

条目可额外包含`company_logo`（已下载并核验的PNG/JPEG本地路径）与`company_logo_source`（核验过的官方来源页面URL，或用户自供图片时填`user-provided`）。脚本不负责下载或判定公司归属；使用logo前须按[公司标识核验规则](grades-self-evaluation-logos.md)检索并确认。相对路径从输入JSON目录解析。官方SVG先做保持比例的格式转换，再嵌入；缺图或缺来源时脚本报错，不静默用错图。两个渲染器都会把标识嵌入公司名称旁，最终仍须人工查看所有页面。

执行：

```bash
python scripts/render_resume.py resume.json resume.pdf --font regular.ttf --bold-font bold.ttf
```

默认只输出可读的一页；超出容量会报错，要求先调整内容。需要两页时，按相同规范使用支持分页的PDF/Word工作流，不自动改回项目符号模板。

## 逐页视觉验收

确认模块顺序、蓝字黑线、日期/名称/角色对齐、三段标签、工作段连续性和页尾结构；检查照片避让、长标题、段落边界、字体嵌入、文字复制与页边距。仅有“生成成功”或文字提取成功，不等于排版通过。
